# Agent Board：Windows Electron 分发设计

日期：2026-08-25  
状态：已确认，等待实施前审阅

## 1. 目标

把当前“需要用户自己安装 Node 并运行 `server.js`”的开发态项目，变成面向 Windows 普通用户的单用户安装包：

- 用户不需要预装 Node.js、npm 或 Python；
- 双击桌面图标即可启动并打开 Agent Board；
- 进程运行无命令行窗口；
- 看板关闭后可缩到系统托盘；
- 同一台机器只运行一个 Agent Board 实例；
- 升级或重装不丢失本地会话数据和用户设置；
- 后端仍只监听 `127.0.0.1`，不向局域网暴露会话内容。

## 2. 本轮范围

本轮实现：

1. Electron 桌面壳；
2. 内置固定版本 Node.js 运行时；
3. 后端作为独立 Node 子进程运行；
4. Windows 单用户安装包；
5. 单实例、托盘、启动/退出和错误提示；
6. 脱离当前开发机路径的运行时配置；
7. 干净 Windows 环境的安装验证。

本轮不实现：

- 自动更新；
- 账号、云端同步和付费鉴权；
- macOS/Linux；
- 默认自动安装全部外部 Agent；
- 代码混淆和强防破解。

旧的 `start.bat`、`start.sh`、watchdog 和 VBS 启动文件暂时保留，仅作为开发/回退入口，不放进首版安装包。待 Electron 版本验证完成后再决定是否删除。

## 3. 总体架构

采用“Electron 壳 + 内置 Node + 后端独立子进程”，不把后端直接塞进 Electron 主进程。

### 3.1 Electron 主进程

Electron 主进程负责：

- 请求单实例锁；
- 启动和停止后端子进程；
- 选择可用的本地端口；
- 等待后端健康检查通过；
- 创建并管理 `BrowserWindow`；
- 创建系统托盘和托盘菜单；
- 处理第二次启动时的窗口聚焦；
- 应用退出时优雅停止后端。

后端安装流程中存在同步 `spawnSync`，因此后端必须保持为独立进程，避免安装或探测阻塞 Electron 主界面。

### 3.2 后端子进程

首版继续复用现有 `server.js`、`lib/` 和 `public/`，不重写业务逻辑。

Electron 开发态使用本机 Node 启动后端；打包态使用安装包内的固定 Node 运行时启动后端。主进程通过环境变量传递：

- `AB_PORT`：后端监听端口；
- `AB_DATA_DIR`：可选的数据根目录；
- `AB_RUNTIME=desktop`：标记当前由 Electron 桌面端启动。

主进程不会依赖解析控制台文字判断服务是否启动，而是轮询 `http://127.0.0.1:<port>/api/state`。后端启动失败、端口被占用或健康检查超时，都显示可理解的错误提示并写入桌面端日志。

### 3.3 窗口和外部链接安全

- `contextIsolation: true`；
- `nodeIntegration: false`；
- 页面继续通过本地 HTTP 地址加载；
- 页面导航只允许当前 Agent Board 本地地址；
- 下载页、Agent 深链等外部地址交给 Electron `shell.openExternal`；
- 不增加任何局域网监听，不把会话正文上传云端。

## 4. 资源布局

安装包内将应用壳和后端资源分开：

```text
resources/
  backend/
    server.js
    lib/
    public/
    tools/wf.dll
    marvis-launch.bat
    zcode-launch.bat
  runtime/
    node.exe
```

后端资源放在 `resources/backend`，不依赖从 `app.asar` 内执行脚本或读取外部文件。Node 运行时固定为 Node 22 Windows x64，初始构建使用项目现有启动脚本中已经验证过的 `22.22.2`，后续升级通过构建配置显式变更。

构建时只复制运行所需的 allowlist 文件，不把测试、设计文档、备份、开发脚本和仓库外数据打进安装包。

Node 运行时来源必须是可追溯的官方发行包，并在发布前保留对应的许可证/第三方声明。

## 5. 运行时路径和依赖修正

### 5.1 数据与用户配置

默认数据目录仍为：

```text
%LOCALAPPDATA%\AgentBoard
```

其中包括现有的 `data.json`、用户路径覆盖和启动覆盖配置。代码增加环境变量覆盖能力，便于桌面端测试、迁移和未来诊断，但普通用户默认不改变现有目录。

安装目录只存程序文件，不存会话数据。

### 5.2 消除开发机硬编码

以下内容必须改为动态解析：

- `AGENT_DEFS` 中 DeepSeek、Marvis、ZCode 的当前机器绝对路径；
- `launch.vbs` 中当前工作区路径；
- 所有依赖当前用户目录的桌面 Agent 可执行文件路径；
- Electron 打包后 `__dirname`、资源目录和用户数据目录的差异。

适配器优先使用当前用户环境变量、注册表、默认安装目录和已有探测逻辑，不把本机开发目录写进发布代码。

### 5.3 移除 Python 隐式依赖

当前 DeepSeek 适配器依赖当前 WorkBuddy 环境中的 Python 路径执行 `decompress-zstd.py`。普通用户不一定安装 WorkBuddy，也不一定有该 Python 环境，因此它不能作为安装包运行前提。

首版改为使用内置 Node 运行时的 zstd 能力完成解压，并保留现有 Python 实现仅作迁移参考或开发回退。打包验证必须覆盖没有 Python、没有 WorkBuddy Python 环境的机器。

### 5.4 窗口激活组件

当前运行时通过 PowerShell `Add-Type` 动态编译 `wf.dll`。打包态改为随应用资源提供预编译的 `wf.dll`，运行时只加载，不再在用户机器上编译 C#。开发态可以保留构建脚本生成能力，但发布路径不能依赖它。

## 6. 启动、托盘和退出行为

启动流程：

```text
桌面快捷方式
  -> Electron 请求单实例锁
  -> 选择本地端口
  -> 启动 resources/runtime/node.exe + backend/server.js
  -> 轮询 /api/state
  -> 创建窗口并加载本地看板
```

行为约定：

- 第二次点击快捷方式：不启动第二个后端，只聚焦已有窗口；
- 点击窗口关闭：默认隐藏到托盘；
- 托盘“退出”：停止后端后退出 Electron；
- 后端异常退出：主进程显示错误通知，不静默生成多个后端；
- 退出时先发送终止信号，等待短暂时间让 JSON 数据保存，超时才强制结束。

是否登录 Windows 后自动启动作为设置项，首版默认关闭，避免安装后突然常驻。

## 7. 安装包

使用 Electron 的 Windows NSIS 单用户安装模式：

- 默认安装到当前用户目录；
- 不要求管理员权限；
- 创建桌面快捷方式和开始菜单入口；
- 不写入系统级服务；
- 不默认添加防火墙规则；
- 卸载程序文件时保留 `%LOCALAPPDATA%\AgentBoard`，避免误删会话数据。

首轮允许生成未签名的内部测试安装包。对外发布前必须补充 Windows 代码签名证书，否则 SmartScreen/杀毒误报风险仍然是发布阻塞项。

## 8. 验收标准

### 8.1 构建

- 在开发机执行桌面开发启动命令可打开 Electron 窗口；
- 构建命令能生成 Windows 单用户安装包；
- 安装包包含后端资源和固定 Node 运行时；
- 安装包不包含测试、文档、备份和当前开发机绝对路径。

### 8.2 干净机器

在没有预装 Node.js、npm、Python、WorkBuddy Python 环境的 Windows 用户环境中：

- 安装过程成功；
- 双击后能打开看板；
- 能完成基础 Agent 探测和会话扫描；
- 后端安装命令仍能按用户确认执行；
- 关闭、托盘、再次打开和退出行为正确。

### 8.3 数据和升级模拟

- 预置旧版 `%LOCALAPPDATA%\AgentBoard\data.json` 后安装新版本，历史会话仍可见；
- 修改过的设置不会因重启丢失；
- 卸载程序后数据文件仍保留；
- 重复启动不会产生第二个后端实例。

## 9. 实施顺序

1. 增加 Electron 桌面入口和开发态启动；
2. 抽出桌面端资源解析、端口选择和后端子进程管理；
3. 修正后端路径、数据目录和 DeepSeek 解压依赖；
4. 加入托盘、单实例和退出流程；
5. 配置 Node runtime 和 NSIS 单用户打包；
6. 补充打包相关单测和启动诊断；
7. 生成测试安装包并执行干净环境验收。

自动更新、签名发布和账号体系在第二阶段单独设计，不混入本轮实现。
