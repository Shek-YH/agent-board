# Agent Board：子代理卡片对叠显示设计

日期：2026-08-28  
状态：方案已确认，等待书面规格复核

## 1. 目标

在不改变现有 Session 拓扑识别和状态判断的前提下，为 Agent Board 增加第二种子代理展示样式。用户可在 `Agent 显示设置` 中选择继续使用现有平铺卡片，或把同一主会话及其子代理显示为一个卡片组。对叠模式下主会话位于最上方，子代理卡片叠在其下并露出底部操作行；主卡上的图标按钮可在对叠和完整展开之间切换。

成功标准：用户能一眼识别子代理属于哪个主会话；现有平铺样式保持默认且不发生视觉回归；找不到父卡的子代理仍然可见；切换展示样式和展开状态不会影响 Session 状态、跳转、已读或更多操作。

## 2. 范围与约束

本轮只改前端分组、设置和样式，不改服务端 Session 数据、各 Agent 适配器或父子关系识别算法。前端继续使用现有字段：

- `id`：带 Agent 前缀的 Session 引用；
- `session_role`：`main`、`child` 或 `unknown`；
- `parent_session_ref`：子代理的直接父 Session 引用；
- `child_count`：主会话的子代理数量摘要。

对叠模式应用于“全部”列和每个 Agent 独立列。无子代理的主卡、未确认卡以及无法安全归组的子卡维持普通卡片显示。

不在本轮范围内：修改拓扑探测、提供树形连线、跨应用重启保存单个卡组的展开状态、改变会话过滤和列排序语义。

## 3. 设置与状态

`Agent 显示设置` 的列勾选区域上方增加“子代理显示样式”：

- `平铺卡片`：保持当前逐张 Session 卡渲染方式；
- `卡片对叠`：启用父子卡片组。

偏好使用独立的 `localStorage` 键保存，值只接受 `flat` 或 `stacked`。缺少、损坏或出现未知值时回退到 `flat`，因此现有用户升级后不会突然改变布局。选项变更后立即重绘看板；“恢复默认”同时恢复默认 Agent 列和 `flat` 样式。

页面内使用一个集合记录已完整展开的根 Session 引用。相同 Session 在“全部”列和 Agent 列重复出现时共享展开状态。该集合不写入 `localStorage`，应用重新打开后，对叠卡组回到紧凑状态。

## 4. 父子分组规则

新增一个无 DOM 依赖的纯分组函数，输入某一列现有顺序的 Session 列表，输出普通卡项和主会话卡组。算法遵循以下规则：

1. 先按 `id` 建立当前列内索引。
2. 对 `session_role=child` 的记录沿 `parent_session_ref` 向上追溯。
3. 只有在当前列内最终追溯到 `session_role=main` 的根卡时，才把该子卡归入根卡组。
4. 多层子代理统一归到根主会话下，子卡之间保持原列表中的相对顺序。
5. 卡组出现在主卡原来的位置；已经归组的子卡不再作为独立卡重复渲染。
6. 父卡缺失、引用不存在、循环引用或无法追溯到主卡时，子卡按原顺序独立显示。

这些回退规则保证筛选范围、历史数据不完整或拓扑异常时不会吞掉任何 Session。

## 5. 卡片组交互与视觉

卡片组由一个主卡、一个伸缩按钮和一个子卡容器组成。现有 `buildCard` 继续负责单张卡片内容和事件，分组层只负责组织 DOM 与展开状态，避免复制跳转、已读、状态和更多操作逻辑。

紧凑对叠状态：

- 主卡完整显示并位于最高层；
- 每张子卡仍保留完整 DOM，但通过负向垂直间距和逐级层叠只露出约一行高度；
- 露出区域覆盖现有底部操作行，保证“更多”“已读”和“跳转”按钮仍可识别、可点击；
- 子卡使用轻微水平错位和递减层级表达卡片数量，主卡内容不被遮挡；
- 紧凑状态关闭子卡原有的悬浮上移效果，避免破坏层叠位置。

完整展开状态：

- 取消负向间距，恢复现有卡片高度和列间距；
- 子卡继续保留现有紫色子代理标识与缩进；
- 所有原有卡片交互保持不变。

伸缩按钮放在主卡第一行右侧，只在卡组确有子卡时出现。按钮使用箭头图标、`aria-expanded` 和动态 `title` 表达当前状态。点击只切换当前根 Session 的紧凑/展开状态，并阻止触发主卡的详情抽屉。平铺样式不显示该按钮。

## 6. 组件与数据流

实现分为三个边界清晰的单元：

1. Session 分组模块：纯函数完成根节点追溯、排序和异常回退，可直接由 Node 测试调用。
2. 看板渲染层：`renderBoard` 根据全局样式选择直接渲染卡片，或渲染分组函数返回的卡组；`buildCard` 接收可选的卡组上下文并为主卡生成伸缩按钮。
3. 设置层：负责读取、校验、保存 `flat|stacked`，渲染两个选项并在变更时调用 `renderBoard`。

数据流为：本地偏好加载 → 列 Session 列表 → 可选父子分组 → 创建卡片/卡组 → 点击伸缩按钮更新页面内集合 → 重绘看板。SSE 仍按现有方式更新运行状态与流光装饰，卡片的 Session 引用不变。

## 7. 兼容与异常处理

- `localStorage` 不可用或内容非法：静默使用 `flat`，不阻断看板。
- 主卡被过滤但子卡仍存在：子卡普通显示。
- 父子引用循环：停止追溯，相关卡普通显示。
- 一个主卡没有实际可见子卡：不生成空卡组，不显示伸缩按钮。
- 子卡处于进行中、刚完成或已读状态：继续复用现有类名和事件，不由分组层重算。
- 现有列顺序、Agent 显隐、详情抽屉、Session 跳转和复制功能不改变。

## 8. 测试与验收

按测试先行实现：

- 分组函数测试：一级父子、多层后代、原顺序保持、父卡缺失、循环引用、普通会话不受影响；
- 设置测试：默认 `flat`、合法值恢复、非法值回退、切换后持久化、恢复默认；
- 渲染契约测试：设置面板包含两种选项；对叠模式生成卡组；只有含子卡的主卡出现伸缩按钮；按钮带有可访问状态；
- 样式契约测试：紧凑层叠、底部露出、完整展开和紧凑态悬浮约束均存在；
- 回归验证：运行完整 `npm test` 与 `git diff --check`。

人工验收时分别查看“全部”列和单 Agent 列，确认主卡、多个子卡、已读按钮、展开/收回以及孤立子卡的表现与设计一致。
